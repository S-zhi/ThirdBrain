# RAG With Cold API Documents

> 让代码 Agent 在调用陌生 / 版本敏感 / 易混淆的 API 时，**有据可查、错了能溯源**。

## 30 秒看懂

- **做什么**：双层架构 — RAG 负责精确事实，大模型负责语义总结，按需路由
- **解决什么问题**：Agent 的「不知道自己不知道」是行业级问题 — 臆造参数、版本错配、同名 API 混淆
- **怎么解决**：namespace 隔离 + 版本强绑定 + 5 阶段 Trace + 长期 Benchmark + 可治理知识图谱
- **不是**：又一个通用 RAG 框架

---

## 核心优势

### ① 双层共存，按需路由（大模型 + RAG 不二选一）

- **大模型**：处理"为什么这样设计"这类**总结性、解释性**内容
- **RAG**：处理"这个参数默认值是多少"这类**事实性、精确性**内容
- **分类检索自动路由**：不用用户判断该问谁
- **链接增强**：用户点击引用时再按需触发大模型深挖，不浪费算力
- **双层解锁机制**：默认走 RAG 强解锁才唤醒大模型，强解锁会有等待提示

> 不是「RAG 准但笨」或「大模型懂但会编」的二选一，而是该谁答谁答。事实用 RAG 拿**准确的**，总结用大模型给**连贯的**。

### ② 知识图谱可治理、可持续自生长

- **可视化**：把语料里的实体和关系画成图谱，不只是一堆散文档
- **可治理**：人手可以增 / 删节点，纠正错误、剔除过期事实
- **可自生长**：大模型识别新知识后自动追加节点，动态扩展
- **承认噪声**：自动生长会产生噪声 — 但手动治理入口兜底，**不会让噪声变成"无法清理的事实"**

> 知识库不再是一摊死水：错了能改、少了能补、噪了能删。

### ③ API 知识精确隔离与防混淆（Namespace 体系）

- **Namespace 隔离**：每个 API 用 `org.product.namespace.version` 唯一标识，跨产品同名 API 互不污染
- **强制版本绑定**：召回结果必须带版本号，过期 API 不会"借"老描述糊弄你
- **防混淆机制**：对易混的命名（不同产品的同名 API），Agent 自动生成**全局唯一名**作为别名
- **上下文区间规划**：namespace 划定数据边界，跨域串台在结构上就不允许

> API 错误使用是 Agent 幻觉的**头号来源**。我们不用「prompt 提醒」解决，而是用 namespace 这种**结构上的隔离**让错都错不进去。

## 你可能没注意到的差异化

### ④ 5 阶段全链路 Trace，出了幻觉能溯源

`trigger → recall → rerank → inject → generate` 五个阶段全部打点。

- 召回到了几条？来自哪个 namespace？哪个版本？
- 重排排到了第几位？为什么被压？
- 注入到 prompt 的具体是哪些 chunk？
- 大模型"实际用了"几条引用？

**出了幻觉能溯源到具体环节**，而不是「RAG 没用好」一句话甩锅。

### ⑤ 长期 Benchmark，升级不靠感觉

可复现、可扩展、可回归的评测 case 集。

- 换 Embedder？跑一遍 Benchmark 看涨了还是跌了
- 调召回阈值？跑一遍
- 升基模？跑一遍
- 涨了是哪类 case？跌了是哪类？**所有变更都有数据支撑**

> 模型升级是黑盒，但我们用 Benchmark 把"黑盒升级"变成"白盒归因"。

### ⑥ 本地优先，部署不挑环境

- **向量后端**：默认 Zvec（in-process 向量库），不强依赖 Postgres + Qdrant 这类重型服务
- **Embedding 主路径**：千问 qwen3.7-text-embedding（2048 维）
- **Embedding fallback**：本地 sentence-transformers MiniLM，**CI / 离线也能跑**
- **CLI + FastAPI 入口**：单机即可起

> 不是只能在云上才能跑起来，本地、CI、离线都能跑。

## 适用 vs 不适用

| ✅ 适合你，如果 | ❌ 不必用，如果 |
|---|---|
| 频繁调用**陌生 / 版本敏感**的 API（云 SDK、内部平台、深度学习算子） | 只是简单 FAQ 问答 |
| 出了幻觉要能**溯源** | 完全不能接受任何"等待" |
| 模型 / Embedder / 检索策略**迭代快** | 不想装任何额外依赖 |
| 需要**私有 / 离线**部署 | — |
| 想把 Agent 调 API 的**正确率当指标**管起来 | — |

---

## 与通用 RAG 的差异

| 维度 | 通用 RAG | 我们 |
|---|---|---|
| 召回粒度 | 文档块 | 带 `org.product.api.vN` 的 API 单元 |
| 版本感知 | ❌ | ✅ 强制 namespace.version |
| 同名 API 隔离 | ❌ | ✅ namespace 隔离 + 防混淆 |
| 输出格式 | 给人的 HTML 段落 | 机器可消费的参数契约 + 反例 |
| 行为可观测 | 黑盒 | 5 阶段 Trace 全打点 |
| 回归测试 | 无 | Benchmark 长期 case 集 |
| 部署门槛 | 通常需要重型向量库 | Zvec in-process |
| 知识治理 | 删文档 | 增 / 删 / 编辑图谱节点 |

---

## 一句话总结

> **我们不解决"Agent 答得对不对"，我们解决"Agent 答错了，能不能追到是知识过时、版本错配、还是 namespace 串了"**。
