# 标签解释

## 标签定义

### 标签1：简单用法

**定义**：针对单个 API 的基础调用场景，不涉及复杂逻辑或多个 API 的组合。

**典型问题模式**：
- 某个 API 的基本调用方式是什么？
- 某个参数怎么用？有哪些合法值？
- API 的返回值是什么结构？
- 如何设置某个配置项？
- API 的版本兼容说明

**判定标准**：
- 涉及 ≤ 3 个 API
- 不需要编写完整代码块，或只需单行/几行调用
- 侧重于 API 的"是什么"和"怎么用"

**示例**：
- "如何设置 pandas.DataFrame 的 multiIndex？"
- "torch.nn.functional.softmax 的 dim 参数传 -1 和 0 有什么区别？"

---

### 标签2：编写代码

**定义**：需要编写完整或较大代码块的问题，涉及多个 API 的组合调用、逻辑编排或完整功能实现。

**典型问题模式**：
- 用某库实现某个完整功能（如"用 OpenCV 实现图像拼接"）
- 多个 API 串联的 pipeline 代码
- 需要处理错误、边界条件的完整函数/类
- 数据处理的完整流程代码

**判定标准**：
- 需要编写 ≥ 5 行的有效代码
- 涉及多个 API 的协调使用
- 有明确的输入输出要求
- 代码需要体现完整的逻辑（错误处理、类型转换等）

**与"简单用法"的区分**：
- 简单用法问的是"单个 API 怎么用"
- 编写代码问的是"用这些 API 完成一个任务"

---

### 标签3：平台适配

**定义**：涉及特定运行平台（操作系统、框架、硬件、部署环境）的差异处理，或某 API 在特定平台下的可用性问题。

**典型问题模式**：
- 某个 API 在 Windows/Linux/macOS 下的行为差异
- 某功能在移动端/桌面端/Web 端的适配方式
- 特定 GPU（CUDA/ROCm/MPS）下的 API 可用性
- 某个库在 Docker/K8s 等容器环境中的使用注意事项
- 跨平台代码的兼容写法

**判定标准**：
- 问题中明确涉及平台、环境或硬件
- 答案可能因平台不同而不同
- 涉及平台限制、fallback 方案、条件编译等

**与"简单用法"的区分**：
- 简单用法不关心在哪个平台运行
- 平台适配的核心是"在这个平台上该怎么处理"

---

### 标签4：其他

**定义**：不属于以上三类，但对评测有价值的问题类型。

**包含场景**：
- **API 对比**：两个功能相似的 API 有什么区别？该用哪个？
- **性能相关**：某个 API 的时间/空间复杂度？如何优化？
- **错误处理**：某个 API 会抛出哪些异常？如何处理？
- **最佳实践**：某个场景下推荐的 API 使用模式是什么？
- **迁移/升级**：从旧版本迁移到新版本，哪些 API 变了？

**判定标准**：
- 问题有明确的评测价值
- 不属于简单用法、编写代码、平台适配的范畴
- 能体现模型对 API 的理解深度

---

## 标签选择规则

1. 每个问题**必须且只能分配一个主标签**
2. 如果问题跨标签（如"在 Windows 上用 OpenCV 写完整代码"），按**核心考察点**选择：
   - 核心是代码编写 → 标签2
   - 核心是平台差异 → 标签3
3. 标签影响评估时的关注点，但评分标准（0/0.5/0.8/1）统一适用
