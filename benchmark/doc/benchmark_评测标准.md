# 评测标准

## 评分体系

采用四级评分制，所有标签类型统一适用。

### 1 分（Pass）— 完全正确

- 函数/API 选择正确
- 参数（名称、顺序、类型）正确
- 执行逻辑正确，输出与预期一致
- **允许合理的实现差异**：不要求与标准答案逐字一致，意思理解正确、逻辑等价即算通过
- 代码可正常运行（如需运行环境）

### 0.8 分 — 基本正确，精度偏差

- 函数/API 选择正确，参数基本正确
- 输出与预期有出入，但属于**精度、格式或细微表达上的差异**，不是方向性错误
- 典型情况：
  - 返回结果精度略低（如小数位数不同）
  - 输出格式有细微差异但不影响语义（如 JSON 字段顺序不同）
  - 功能实现正确但有非关键性冗余步骤

### 0.5 分 — 方向性错误

- **函数选错了**：调用了错误的 API，或该场景下不应使用此函数
- **参数错误**：函数选对了，但关键参数传错（名称错、顺序错、类型错），导致运行结果与预期不一致
- **幻觉严重**：生成了不存在的 API、不存在的参数、或虚构的功能行为
- 代码可能能运行，但结果明显不对

### 0 分 — 重大错误

- 代码无法运行（语法错误、import 错误、基础结构错误）
- 完全没有理解问题意图，答非所问
- 输出了与问题无关的内容
- 代码框架缺失，只有片段无法构成完整逻辑

## 评判原则

### 宽松判定

- **语义等价即正确**：不要求与标准答案完全一致，实现方式可以不同，只要最终行为正确即可
- **允许合理变体**：同一功能可以有多种实现路径，只要使用了正确的 API 且结果正确即可

### 严格判定

- **API 选择错误直接降档**：用错了函数，即使结果碰巧接近，最高 0.5 分
- **不存在的 API/参数**：任何幻觉内容，最高 0.5 分
- **代码不可运行**：语法级别的错误，直接 0 分

## RAG 效果对比维度

每个评测问题在两种条件下分别测试：
1. **无 RAG**：仅凭模型自身知识回答
2. **有 RAG**：提供 API 文档作为检索上下文后回答

对比结果判定：
- **改善（+）**：有 RAG 的评分 > 无 RAG 的评分
- **退化（-）**：有 RAG 的评分 < 无 RAG 的评分
- **无变化（=）**：两次评分相同

改进率 = (有RAG的Pass率 - 无RAG的Pass率) / 无RAG的Pass率
