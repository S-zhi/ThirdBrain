## 评测目标
这些评测问题用于评估 RAG 系统对 LLM 代码生成能力的帮助程度。问题应当：
- 有明确的考察点（某个 API 的具体用法或对比）
- 答案可以从给定的 API 文档中找到依据
- 能区分"看过文档"和"没看过文档"的回答质量差异

## 生成要求

请生成 {question_count} 个评测问题。根据选取模式：

### 单 API 模式
- 针对该 API 的用法、参数、返回值、边界条件等出题
- 问题应当具体，避免泛泛而谈

### 多 API 对比模式
- 生成对比性问题，如"A 和 B 有什么区别？""什么场景下该用 A 而不是 B？"
- 对比点应当是文档中有明确说明的

### 混合模式
- 以主 API 为基础出题，结合关联 API 做对比或组合使用

## 标签分配规则

每个问题必须分配一个标签，可选标签及判定标准：

| 标签 | 定义 | 判定标准 |
|------|------|---------|
| 简单用法 | 单个 API 的基础调用 | 涉及 ≤ 3 个 API，侧重"是什么"和"怎么用" |
| 编写代码 | 需要完整代码块 | 需要 ≥ 5 行代码，涉及多 API 组合 |
| 平台适配 | 特定平台/环境的差异处理 | 问题明确涉及 OS、硬件、框架、部署环境 |
| 其他 | 不属于以上三类 | API 对比、性能、错误处理、最佳实践等 |

---

## 输出格式

请严格按以下 JSON 格式输出，不要输出其他内容：

```json
{
  "questions": [
    {
      "question": "评测问题文本",
      "tag": "简单用法|编写代码|平台适配|其他"
    }
  ]
}
```

要求：
- 问题应当自然、像真实用户会问的编程问题
- 每个问题必须有明确答案，且答案可从文档中找到
- 标签分配要准确，严格按上述标准判断
- 如果生成了多个问题，尽量覆盖不同的标签类型
