# 评分规则

请根据以下四级标准，对模型输出进行评分：

| 分数 | 标准 |
|------|------|
| **1.0** | 完全正确：使用了正确的 API、参数、调用方式，与标准答案一致或功能等价 |
| **0.8** | 基本正确：API 使用正确，但存在非关键细节偏差（变量名不同、顺序略异、缺少非关键参数等） |
| **0.5** | 部分正确：识别出了相关 API，但调用方式有明显错误（参数错误、缺少必要步骤、调用链不完整） |
| **0.0** | 完全错误：未使用正确的 API，或完全偏离问题，或输出无意义内容 |

## 评判要点说明

重点关注以下方面：

1. **API 识别**：模型是否选对了要使用的 API？（对照标准答案和参考文档）
2. **参数正确性**：参数名称、类型、顺序是否正确？
3. **调用完整性**：是否遗漏了必要的步骤（如初始化、配置、错误处理）？
4. **代码可运行性**：给出的代码片段逻辑上是否能跑通？

## 宽容条款

以下情况不应扣分：
- 变量命名不同（不影响功能）
- 代码风格差异（缩进、换行、注释）
- 使用了等价的不同写法（如 `import x as y` vs `from x import y`）
- 额外的错误处理或边界检查（加分项，不扣分）

## 严格条款

以下情况必须扣分：
- API 名称拼写错误或使用了不存在的 API
- 必选参数缺失或传错
- 调用顺序错误导致逻辑不通
- 生造了 API 文档中不存在的方法或功能

# 输出格式

请严格按以下 JSON 格式输出，不要输出其他内容：

```json
{
  "score": 0.0,
  "reason": "对得分的可读解释。最后一句必须是：因此，应该给出的分数是X.X"
}
```

**字段说明：**
- **score**：最终得分，必须是一个 0.0 到 1.0 之间的数字，表示满足评分标准的程度。1.0 表示完全满足，0.0 表示完全不满足。
- **reason**：对得分的可读解释。最后必须用一句话结束：`因此，应该给出的分数是你的评分`。
